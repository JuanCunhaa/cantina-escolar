## 20. Testes e critérios de aceite obrigatórios

Faça testes de domínio em TypeScript, integração com Firebase Emulator Suite (Auth e Firestore; arquivos contra o armazenamento local, que é um double do R2, mais um servidor S3 duplo para o contrato do cliente e uma integração opcional com bucket R2 de homologação), testes de Security Rules e E2E dos caminhos principais. Inclua testes concorrentes das transações. Mock não prova rules ou integridade; emulador não é evidência de todos os comportamentos/índices/latência de produção, então valide também o fluxo em projeto de homologação com valores fictícios e gateway sandbox. Testes devem verificar regras do negócio e riscos reais.

## Evidências do e2e no CI (observabilidade)

Quando `npm run test:e2e` falha no CI, o workflow publica o artefato `e2e-evidencias-<run>-<tentativa>` (retenção 7 dias) com `test-results/` (resultados, `error-context.md`, traces `retain-on-failure`), `playwright-report/` (HTML; abrir com `npx playwright show-report`, os traces abrem por ele) e `ci-diagnostics/resources.txt` (CPUs, carga, memória, limites de cgroup e os maiores processos por memória: no início do e2e, com os serviços ativos ao terminar — globalTeardown — e depois que saem). Só dados fictícios do emulador; nada de `.env`, variáveis ou argumentos de processo. O passo dos testes continua definindo o status do job; timeouts, tentativas e asserções não mudaram. Serve para examinar a PRÓXIMA ocorrência das falhas intermitentes de `wallet.spec.ts` e `students.spec.ts` (causa desconhecida; esta mudança não as resolve). Baixar: `gh run download <run> -n e2e-evidencias-<run>-<tentativa>`.

Validação da coleta (05/10/2026): com uma falha controlada temporária numa PR descartável (não mesclada), o job falhou, o artefato `e2e-evidencias-<run>-1` foi gerado (≈ 29 MB, expira em 7 dias) com 110 arquivos de trace, os `error-context.md`, o relatório HTML e `resources.txt`; o mesmo run capturou duas falhas intermitentes reais adicionais (`policies.spec.ts:26`, `shell-photos.spec.ts:139`) já com evidência. O runner tem 2 CPUs e 7,9 GB; a carga medida com os serviços ativos foi 3,4–4,4 (acima das 2 CPUs). Isto é medição, não diagnóstico de causa.
