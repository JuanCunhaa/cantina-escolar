### 18.2 Security Rules e arquivos

Negue por padrão. Clientes podem ler apenas os documentos que suas permissões permitem e não podem escrever saldo, movimentos financeiros, preços autorizados, estoque, papéis, vínculos ou agregados. Preferencialmente, todas as alterações de negócio passam pelo servidor. Rules devem suportar listeners familiares de pedidos/carteira sem abrir coleção geral.

Lembre que rules autorizam documento inteiro, não ocultam campos individuais. Separe cadastro público de produto dos dados de custo/fornecedor, e perfil necessário de aluno dos dados administrativos restritos. Projeções de leitura são permitidas para essa separação; atualize-as de forma controlada. Não utilizar filtro visual como segurança.

Arquivos (R2, desde 01/10/2026): não há Storage Rules. O bucket é privado e só o servidor o acessa; as garantias antes dadas pelas Rules (somente cantina/admin enviam, tipo/tamanho, sem sobrescrita, leitura só por perfil ativo, revogação imediata pelo perfil atual) agora são impostas pelo servidor (`requireActor`, `catalog.photos.manage`, bytes inspecionados, chave gerada no servidor, `If-None-Match`) e provadas em tests/integration/photo-route.test.ts. Firestore guarda só metadados e a chave do objeto (nunca URL assinada ou pública); o campo de foto é escrito apenas pelo servidor (Rules negam escrita do cliente). Comprovantes privados não recebem URL pública permanente nem token compartilhável. Limpeza de uploads abandonados: `sweepOrphanPhotos` (POST /api/admin/storage/sweep, dry-run por padrão). Substituição de foto: decidido em F06 que o snapshot do pedido não inclui a foto; a chave anterior é apagada após o commit. Catálogo (F06): `categories`/`products` legíveis por perfil ativo, `products/*/priceHistory` por cantina/administração, `productPrivate` (fornecedor/observações) só administração; escrita sempre negada ao cliente. Cardápio (F07): `defaultMenuRules` e `menuOverrides` (com motivos internos) legíveis só por cantina/administração; família/aluno recebem apenas o cardápio resolvido pelo servidor (`GET /api/menu`, com vínculo/aluno próprio atuais); escrita sempre negada ao cliente. As regras F07 só acrescentam leitura (expandir), compatíveis com a versão publicada da main.
