# F04 — Alunos, responsáveis, vínculos e convites

Etapa: B. Dependências: F03. Estado inicial: pendente.

## Resultado exigido

Implementar CRUD/arquivamento, turmas/turnos, matrícula única, homônimos, múltiplos responsáveis sem principal, vínculos autorizados, login opcional de aluno, convite de uso único/expirável e importação CSV com prévia/duplicidades. Não permitir auto-vínculo por busca de nome.

## Skills integradas à execução

Acionar a skill indicada quando chegar à etapa correspondente; não carregar todas de uma vez. Usar a ferramenta Skill do Claude Code quando disponível. A invocação carrega instruções; implementar o resultado e gerar evidência continua sendo responsabilidade do agente.

1. **Use `/cantina-token-economy` para contexto:** Obter metadados desta tarefa pelo script e reduzir buscas/saída sem remover invariantes.
2. **Use `/cantina-testing` para casos de teste:** Planejar/implementar casos dos IDs de aceite relevantes; não rodar a suíte completa nesta etapa.
3. **Use `/cantina-firebase` para persistência e integração:** Implementar documentos, consultas, índices, listeners, Auth, Firestore e/ou transações Firebase afetados; arquivos/fotos pelo módulo de Storage R2 (src/lib/storage), nunca Firebase Storage.
4. **Use `/cantina-ui` para interface:** Implementar telas funcionais e verificar a direção clean, fotos, acessibilidade e estados.
5. **Use `/cantina-security` para revisão de acesso e risco:** Revisar os arquivos/comandos alterados, autorização e caminhos negativos; usar scanners quando pertinentes.
6. **Use `/cantina-verify` para validação:** Executar checks já planejados, sem repetição desnecessária, e registrar evidência/pendência por critério.

Condicionais: `cantina-research` só quando faltar informação oficial; `cantina-debug` se houver falha. Não repetir checks já comprovados sem mudança relevante. Se ferramenta Skill não estiver disponível, ler o SKILL.md correspondente e registrar uso por leitura, sem afirmar invocação automática.
